# 农行境外贵宾休息室查询站设计

## 背景

当前目录的 `W020260702557021741944.xlsx` 包含 1024 条农行境外贵宾休息室数据。表格字段包括：州、国家、城市、站点、三字码、航站楼、名称、出发类型、安检类型、位置指引。直接用表格筛选在手机端不方便，目标是做一个可部署到 Vercel 的移动端优先查询网页。

## 目标

- 不做后端，使用静态 Next.js 页面部署到 Vercel。
- 将 Excel 数据清洗为静态 JSON，随前端一起发布。
- 页面打开后直接进入查询体验，不做营销首页。
- 使用选择框作为主要筛选控件，避免用户在长列表中滑动太久。
- 筛选项要级联联动：上级条件变化后，下级选择项只显示当前结果集内可用值。
- 页面要美观、有设计感，并且适合手机端单手使用。

## 非目标

- 不提供后台编辑、登录、权限管理或数据库。
- 不在首版提供地图导航、收藏、分享卡片或机场实时状态。
- 不修改源 Excel 文件。

## 用户体验

页面顶部展示简洁标题、数据总数和当前匹配数量。主操作区由一个关键词搜索框和一组选择框组成。选择框顺序为：

1. 州
2. 国家
3. 城市
4. 机场 / 三字码
5. 航站楼
6. 出发类型
7. 安检类型

所有选择框按当前筛选结果动态生成选项。例如选择“亚洲”后，国家下拉框只显示亚洲内的国家；继续选择“日本”后，城市、机场、航站楼等选项只显示日本相关值。用户修改上级筛选条件时，如果下级已选值不再可用，系统自动清空该下级值。

关键词搜索覆盖城市、国家、机场、三字码、休息室名称、航站楼、出发类型、安检类型和位置指引。结果以移动端卡片展示，卡片优先显示城市、机场、三字码、休息室名称、航站楼、出发类型、安检类型和位置指引。

## 视觉方向

整体风格是精致、清爽、偏高端的机场贵宾厅查询工具。布局不使用营销式大首页，而是把查询工具作为首屏。手机端优先，桌面端以居中宽容器承载同一套体验。控件尺寸要适合触控，卡片信息层级清楚，筛选区和结果区之间要有明确分隔。

## 架构

- 使用 Next.js + React + TypeScript。
- 使用静态 JSON 数据文件作为唯一数据源。
- 使用一个数据转换脚本从 Excel 生成前端 JSON。
- 前端筛选逻辑封装为纯函数，便于测试。
- Vercel 以标准 Next.js 项目部署。

## 数据处理

转换脚本读取 `贵宾厅境外机场清单` sheet，忽略空的 `Sheet1`。每条记录生成稳定 id，并保留原始字段。字段名转换为更适合前端使用的英文 key：

- continent
- country
- city
- airport
- code
- terminal
- loungeName
- departureType
- securityType
- directions

空值保留为空字符串，前端展示时用“未注明”兜底。

## 筛选规则

筛选分两层：

- 匹配结果：根据当前所有已选条件和关键词得到。
- 选择项：每个选择框的可选值基于“除自身条件外的当前条件”生成，这样用户可以在同级范围内切换，同时仍受其他条件约束。

对于包含逗号的字段，如出发类型，展示和筛选时按独立标签处理。例如“国际出发,国内出发”会同时归入“国际出发”和“国内出发”。

## 错误与空状态

- 无结果时展示清晰的空状态，并提供“清空筛选”操作。
- JSON 数据为空或加载失败时展示错误提示。
- 位置指引为空时展示“未注明”。

## 测试与验证

- 验证 Excel 转 JSON 的记录数、字段完整性和样例数据。
- 验证级联选择框不会出现当前条件之外的选项。
- 验证修改上级筛选会清空无效下级选择。
- 验证关键词搜索可匹配机场、三字码、休息室名称和位置指引。
- 构建通过后启动本地服务，用手机和桌面视口检查布局、文本不溢出、卡片可读。
